# vv Boss View

This file is v1.6's second mode.

`conductor.md` handles "how to do it."
`boss-view.md` handles "what to do first today."

## When to Use It

When you don't know what to push first today, or you feel like you have too many things going on, say this to vv:

```text
vv, switch to Boss View and help me see what I should tackle first today.
```

vv should not dispatch work right away. It judges first.

## Required Reading Before Starting

1. `~/vv-memory/00_index.md`
2. `~/vv-memory/01_who-i-am.md`
3. The handoff or project summary for every project currently in flight
4. `~/vv-memory/03_ai-work-rules.md`

## Answer Format

```text
Memory signal:
The full picture I'm currently seeing:
Today's top recommendation:
Why this one:
Forgotten but risky:
What needs your sign-off:
Here's how you can reply:
```

## Priority Judgment Order

When vv ranks priority, it follows this order:

1. Anything with money, customer, legal, account, or data-safety risk.
2. Anything someone is already waiting on you to reply to or sign off on.
3. Anything that, once done, unlocks a lot of other work.
4. Anything close to a deadline, an expiry, or a timing window.
5. Pure organizing, pure polish, pure idea expansion.

## What Not to Do

- Don't list every project evenly and make the user pick.
- Don't just say "they all seem important."
- Don't write code directly in Boss View.
- Don't make the business call on the user's behalf — only give a recommendation and reasoning.

## Recommendation Sentence Patterns

```text
I'd recommend pushing A today — not because B doesn't matter, but because finishing A unlocks both B and C.
```

```text
This isn't a build problem right now, it's a sign-off problem — once you decide the direction, it's worth dispatching.
```

```text
This project can pause for now — that's not giving up, it's just that pushing it right now has a lower return than the other one.
```
